# Phase 07 — CI gating and build/toolchain coherence

> **Recommended Codex model: GPT 5.5 medium** (`reasoning_effort: medium`)
>
> Moderate, mostly mechanical multi-file work: add a dbus-backed Nix check, add a
> CI workflow that runs `nix flake check`, reconcile a nightly `.cargo/config.toml`
> against a pinned stable toolchain, and drop unused deps. The one non-trivial bit
> is running the integration tests inside (or alongside) the Nix sandbox where no
> session bus exists — that needs `dbus-run-session` wiring and possibly relaxing
> sandbox constraints, a known pattern. `medium` fits; not `high` (no cross-system
> design), not `low` (the dbus-in-check step has a real failure mode).

## Goal

CI reproducibly gates the whole stack: `nix flake check` (patch-applies +
clippy + a new dbus-backed integration check) runs in committed CI, the working
tree's `.cargo/config.toml` no longer breaks ad-hoc `cargo` against the pinned
stable toolchain, and unused dependencies are removed.

## Why this matters now

Audit findings:

1. **Test-gap — `doCheck = false` + mock-only CI.** [flake.nix](../../../flake.nix)
   sets `doCheck = false` (integration tests need a live D-Bus, unavailable in
   the sandbox), so `nix flake check` never runs the ~40 protocol tests; the only
   committed CI (`.woodpecker.yml`, under the mock crate) runs only fmt/clippy/
   test for the mock and never builds the five patched packages or runs the Nix
   patch-apply checks. Patch drift against upstream — the series' whole value
   proposition — is ungated.
2. **Nix-build/medium — toolchain incoherence.** The untracked
   `.cargo/config.toml` (generated by rs-harbor) enables nightly-only features
   (`[unstable] codegen-backend`, `profile.dev.codegen-backend = "cranelift"`,
   rustflags `-Zshare-generics=y` / `-Zthreads=0`) while
   [rust-toolchain.toml](../../../rust-toolchain.toml) pins **stable**. A stable
   `cargo` in the working tree rejects the `-Z` flags. (It is untracked, so a
   fresh clone is unaffected — but it breaks the local devShell `cargo`.)
3. **Low/maintainability — unused deps.** `tracing`, `tempfile` (runtime) and
   `tracing-subscriber` (dev) are unused in `screencast-portal-mock`.

## Out of scope

- Do **not** change the pinned nixpkgs revisions.

## Plan

1. **Add a dbus-backed integration check.** In `flake.nix` `checks`, add a
   `mock-tests` check that runs the suite under a private session bus — e.g. a
   `craneLib.cargoNextest` / `cargoTest` derivation with `dbus` in
   `nativeCheckInputs` and a `checkPhase` (or `preCheck`) wrapping the runner in
   `dbus-run-session -- …`. If the sandbox forbids the bus socket, gate it behind
   the appropriate mechanism (a `__noChroot`/`requiredSystemFeatures` build, or
   keep the package `doCheck=false` but add a *separate* check derivation that
   sets up the bus). Document the chosen approach in a flake comment.
2. **Add a committed CI workflow** that runs `nix flake check` (covering all
   `*-patch-applies` builds + `mock-clippy` + the new `mock-tests` check). Place
   it where the project's CI lives (the repo uses Woodpecker under the mock
   crate; add a top-level workflow that builds the flake). Keep it cheap: rely on
   the Nix store / Attic cache if configured.
3. **Reconcile the toolchain.** Make `rust-toolchain.toml` (stable) authoritative
   for ordinary builds: either add `.cargo/config.toml` to `.gitignore` (it is
   rs-harbor-generated and untracked) so it never leaks into the repo, or gate
   the nightly fast-build config behind an opt-in that does not break a stable
   `cargo`. Confirm `cargo build`/`cargo test` work in the devShell after the
   change.
4. **Drop unused deps.** Remove `tracing`, `tempfile`, and `tracing-subscriber`
   from `screencast-portal-mock/Cargo.toml` (verify with a grep that they are
   truly unreferenced across `src/`, `tests/`, `examples/`; coordinate with
   [Phase 06](./06-mock-fidelity-coverage.md) in case its new code legitimately
   uses one — if so, keep that one).
5. **Verify.** `nix flake check` passes including the new check; the devShell
   `cargo test` runs; `cargo clippy -- -D warnings` clean.

## Acceptance criteria

- [ ] `nix flake check` runs a `mock-tests` (or equivalently named) check that
      executes the integration suite under a D-Bus session bus and passes.
- [ ] A committed CI workflow runs `nix flake check` (patch-applies + clippy +
      integration), not just the mock fmt/clippy/test.
- [ ] Ad-hoc `cargo build`/`cargo test` in the devShell works against the pinned
      stable toolchain (the nightly `.cargo/config.toml` no longer breaks it; it
      is gitignored or made opt-in).
- [ ] `tracing`, `tempfile`, `tracing-subscriber` are removed from
      `screencast-portal-mock/Cargo.toml` (unless Phase 06 introduced a real use).
- [ ] `cargo clippy -- -D warnings` is clean after dep removal.

## Pitfalls

- **Symptom:** the dbus check fails in the Nix sandbox with "Failed to connect to
  bus". **Cause:** no session bus / no abstract sockets in the sandbox.
  **Recovery:** use `dbus-run-session --`; if that still fails under sandboxing,
  use `__noChroot`/`requiredSystemFeatures` or run the integration suite in the
  CI workflow step outside the sandbox while keeping patch-apply checks in
  `nix flake check`.
- **Symptom:** removing `tempfile` breaks a `PrivateBus` temp dir. **Cause:** an
  actual (if indirect) use. **Recovery:** re-grep; keep deps that are genuinely
  referenced.
- **Symptom:** CI is very slow building five C/C++/Rust packages. **Cause:** cold
  cache. **Recovery:** wire the Attic substituter if available; otherwise accept
  the cost or split patch-apply checks to run on patch-file changes only.
- **Symptom:** gitignoring `.cargo/config.toml` doesn't help an existing working
  tree. **Cause:** the file still exists locally. **Recovery:** the devShell must
  work with it present — either the opt-in gating, or instruct (in a flake/devShell
  note) that the generated file be removed; the acceptance is "devShell cargo
  works".
